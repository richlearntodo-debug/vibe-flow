# Vibe Flow V2.0 UI 与交互规范

> **历史归档（2026-09-08）：** 本文件记录早期“离键闭环”范围，当前产品 UI 已收口为首页、快捷键、语音、自检和设置。原 Project Spaces 用户面（含 APP 入口管理）已移除并归档，本文件中的项目、截图和浏览器流程仅作历史审计。

更新日期：2026-09-03  
状态：已批准产品提示词的阶段化实现规范  
技术边界：现有 .NET Framework WinForms 增量重构

## 1. 设计目标

V2.0 只服务一个闭环：进入项目现场，锁定正确输入目标，按住说需求，用户目视检查并手动发送，切到预览，浏览和截图，再把截图安全粘贴到已验证目标并继续语音说明。

优先级从高到低：

1. 冻结录音链路不回归。
2. 录音键和设备输入路由不回归。
3. 旧配置和 Profile 不丢失、不被静默覆盖。
4. 状态真实且可恢复。
5. 新功能最小闭环。
6. 视觉优化。

## 2. 不可跨越的交互边界

- 录音始终按住开始、松开结束；录音键不出现在普通映射、新页面导航或 V2 动作中。
- 录音开始后，Focus、Project Space、Capture & Ask、Deck 必须停止后续抢焦点步骤。
- 不读取、保存、上传或重新插入第三方转写文字。
- 不自动按 Enter，不显示“转写完成”“AI 已收到”“开发服务器已启动”。
- 截图只能由用户显式触发，不读取剪贴板文字，不自动发送。
- Project Space 不能携带任意 shell、脚本、附加命令参数或部署动作。
- HUD 和录音时的 Deck 不激活、不抢焦点、不遮挡关键输入。
- 新功能关闭或未配置时，旧用户行为与 V1.5 相同。

## 3. 状态模型

所有异步 UI 使用同一状态集合：

| 状态 | 含义 | CTA 规则 |
| --- | --- | --- |
| `idle` | 尚未开始 | 显示一个主要操作 |
| `checking` | 正在验证前置条件 | 禁止重复提交，可取消时显示取消 |
| `running` | 已开始可观测动作 | 显示当前步骤和耗时 |
| `success` | 已收到真实成功回执 | 只描述实际确认的结果 |
| `warning` | 动作部分完成或需要用户确认 | 显示影响与下一步 |
| `error` | 失败且未执行后续危险动作 | 显示原因、影响、修复、重试、错误码 |
| `canceled` | 用户取消或录音优先中止 | 不显示为成功，不执行后续步骤 |

统一结果至少包含：`actionId`、动作名称、目标稳定 ID、状态、阶段、用户文案、错误码、恢复动作、开始/完成时间和耗时。日志只保存稳定 ID、策略、状态、错误码和耗时；去除用户文字、完整窗口标题、截图、蓝牙地址和不必要的完整路径。

## 4. 视觉系统

- 默认浅色，支持深色和跟随 Windows。
- 8 px 间距网格；卡片圆角 10–14 px；按钮/输入框高度 38–44 px。
- 主标题 24–28 px；页面标题 20–24 px；分区标题 15–18 px；正文 13–14 px；辅助文字 11–12 px。
- Primary 使用品牌紫；Accent 青色只辅助；Success 绿色；Warning 琥珀；Error 红色；Neutral 使用灰白/深灰表面。
- 状态必须同时有图标、文字和颜色；不能只靠颜色。
- 去除无信息价值的渐变、光晕、密集圆点和装饰动画。
- 默认只突出一个主 CTA；页面中次要动作使用次按钮或文本按钮。

## 5. 布局与可访问性

- Form 使用 `AutoScaleMode.Dpi`，优先 `TableLayoutPanel`、`FlowLayoutPanel`、Dock、Anchor 和 AutoScroll。
- 页面主要任务在 1366 x 768 首屏可达；不依赖横向滚动。
- 目标验证：100%、125%、150%、200% DPI；1920 x 1080 与 1366 x 768；浅色、深色、跟随系统。
- 长中文允许换行；按钮不得被裁切；主要 CTA 保留最小宽度。
- 所有操作支持 Tab 导航、清晰焦点框和 Escape 取消（适用时）；不可依赖不稳定 Back 键。
- 打开/关闭对话框必须释放临时 Hook、映射状态、修饰键和取消令牌。

## 6. 主信息架构

左侧导航固定为：

1. 首页
2. 项目
3. 按键
4. 语音
5. 自检
6. 设置

阶段 1 只建立六页壳和等价旧功能，不同时引入 Focus/Project/Capture 业务。

### 6.1 首页

首页回答四个问题：现在能否使用、会输入到哪里、实体键做什么、下一步是什么。

从上到下：

- 全局状态条：设备、语音桥接、Profile、Smart Focus 目标。
- 主状态卡：只显示当前最重要问题或推荐动作。
- 最近 Project Space 与“进入项目”。
- 快捷操作：锁定目标、截图提问、打开预览、查看 Deck。
- 遥控器缩略图和最近实体键高亮。
- 最近一次真实回执。
- 自检异常摘要与修复入口。

未设置目标：`尚未设置输入目标` + `设置第一个目标`。录音停止后的标准文案：`录音已结束，等待语音工具处理；最终文字请目视确认`。

### 6.2 项目

- Project Space 卡片：名称、编辑器、目录脱敏摘要、预览域名、Profile、Focus 目标、上次结果。
- 卡片动作：进入、编辑、复制、删除；删除二次确认。
- 空状态主 CTA：`创建 Vibe Coding 项目现场`。
- 创建向导 5 步：名称与编辑器、目录与预览、辅助资源、Profile 与目标、执行预览。
- 执行视图逐步显示 checking/running/success/warning/error/canceled、耗时、错误码和下一步。

### 6.3 按键

- 保留 Profiles、应用绑定、快捷键录制和 Bridge revision ACK。
- 左/中区域显示遥控器实际键位，选中键高亮。
- 右侧显示短按/长按动作、冲突、测试、保存/ACK 状态。
- 录音键只读显示“固定按住说话”，永远没有编辑入口。
- V2 动作可选 Smart Focus、Capture & Ask、打开 Deck、进入 Project Space，但默认不绑定。
- Home 长按推荐必须显示现有值与推荐值差异，由用户确认，可撤销。

### 6.4 语音

- 显示稳定语音链路、第三方工具、快捷键、触发方式、端点和当前 Focus 目标。
- 真实测试分开显示：收到真实音频、语音工具已被唤起、最终文字需要用户目视确认。
- 高级参数默认折叠且保留明确警告；偏离稳定档时提供预览后恢复。
- 不使用“转写完成”作为 Capture 或音频派发结果。

### 6.5 自检

分为核心环境、语音链路、V2.0 场景能力。保留 V1.5 现有 10 项，再增 Focus 目标、截图/剪贴板图像、Project Space 资源、浏览器模板、HUD/Deck 显示能力。

每项都必须显示：目标状态、当前证据、原因、影响、建议操作、修复/设置入口、重新检测和错误码。

### 6.6 设置

分组：外观、后台与开机启动、HUD 与通知、隐私和本地数据、更新、诊断和重置。危险重置显示具体影响、保留项和二次确认。提供“重新打开首次设置”。

## 7. Live HUD

- 轻量、置顶、默认不激活；使用 WinForms `ShowWithoutActivation` 和适当扩展样式。
- 状态来源必须是统一结果或现有真实运行回执。
- 显示设备连接、语音桥接、Profile、Focus 目标、实体动作、真实音频、录音结束等待工具、Project Space 步骤、截图复制/粘贴派发和错误。
- 普通成功短暂消失；错误和需用户操作的 warning 停留更久；时长可调、HUD 可关闭。
- 重复请求去重；录音中不得抢焦点。

## 8. Context Deck

- 只读解释面板，不建立第二套 Raw Input 或遥控器导航状态机。
- 显示当前应用、Profile、Project Space、Focus 目标、遥控器实际映射、最近结果、设备与语音状态。
- 同一次输入只由现有 Bridge 执行动作，Deck 只消费回执并高亮。
- 首页、托盘或用户明确绑定的普通按键可打开；不自动覆盖 Home 长按。
- 录音开始时缩为 HUD 或保持不激活，不遮挡目标输入。

## 9. Smart Focus

- Target 卡片：名称、所属应用、识别策略、状态、最后验证时间、立即测试、重新学习、删除。
- 学习只接受所选进程中可获得键盘焦点且具有编辑语义的稳定 UIA 元素。
- 持久化 descriptor：processName、AutomationId、ControlType、ClassName、稳定父结构指纹、策略、最后验证时间；不保存 Value、标题正文、网页正文、RuntimeId 单点身份或屏幕坐标。
- 执行顺序：单实例请求 → 检查未录音 → 激活应用 → 等窗口稳定 → 查找/聚焦 → 验证焦点 → 成功回执。
- 任一步失败都不发送快捷键、不粘贴；录音开始立即取消后续抢焦点步骤。
- 未真机验证的 Cursor/VS Code 适配器必须标记“设计支持/未验证”，不能写“已验证”。

## 10. Project Spaces

- 数据：稳定 ID、名称、图标/首字母、编辑器、workspace、可选终端、预览 URL、可选仓库/文档 URL、Profile、默认 Focus/Capture 目标、启用、最近使用。
- 允许步骤仅为 `OpenOrActivateApp`、`OpenWorkspaceWithVerifiedAdapter`、`OpenUrl`、`SwitchProfile`、`FocusTarget`、`ShowNotification`。
- URL：HTTP 只允许 localhost、127.0.0.1、[::1]；其他只允许 HTTPS；拒绝 javascript/data/file 等协议。
- 不接受任意命令、附加 CLI 参数、脚本或环境变量展开。
- 执行使用保存时快照、全局单实例、默认失败即停、可取消；取消只停止后续步骤，不伪装回滚已打开应用。
- 打开 URL 只说明“预览地址已打开”，不能说明服务已启动。

## 11. Capture & Ask

- 流程：当前窗口/区域截图 → 预览 → 复制或发送到目标 → Focus 验证 → 写入本次图像剪贴板 → 粘贴派发 → 提示用户按住录音键说明并手动发送。
- 预览与粘贴必须引用同一图像对象/文件身份。
- 临时图片位于用户数据专用 temp 子目录；成功、取消、超时、下次启动清理。
- 不读取原剪贴板文字，不 OCR、不上传、不自动录音、不自动发送。
- 目标失败时：`未找到输入目标，未执行粘贴`。
- 粘贴后最多显示“粘贴动作已派发”或有证据时“目标检测到图像”，不能显示“AI 已收到”。

## 12. Browser Remote Lite

- 是受约束 Profile 模板，不开发浏览器扩展和网页语义导航。
- 显示现有配置与推荐配置差异；用户逐项或整体确认后才应用；保存应用前快照并支持一键撤销。
- 默认建议：上 Page Up、下 Page Down、左 Browser Back、右沿用已验证行为、确认 Enter、功能键短按刷新、长按由用户选择地址栏或查找。
- TV 默认保留 Task View；Home 长按只推荐、不自动修改。
- Chrome/Edge/Firefox/Brave 的“已验证”标签只能来自本轮真机记录。

## 13. 唯一 5 任务首次设置

1. 理解 hold-to-talk、约 60 秒边界、隐私和手动确认。
2. 配对并验证真实遥控器方向键事件。
3. 检测 RC003 ATVV、CABLE Input、CABLE Output，安全处理重启恢复。
4. 选择语音工具、验证唤起和真实音频，最终文字由用户目视确认。
5. 个性化后台/托盘/可选 Smart Profiles，并引导 Project Space、Browser 模板和 Focus 目标。

每步固定结构：目标、为什么、当前状态、主操作、重新检测、问题/影响/修复、上一步/下一步、进度保存。按钮点击本身不能完成任务；自动检测与用户目视确认分开记录。

## 14. 文案模板

推荐：

- `目标已锁定：Cursor Chat`
- `录音已结束，等待语音工具处理`
- `音频已交给语音工具；最终文字请目视确认`
- `截图已复制到剪贴板`
- `粘贴动作已派发，请按住录音键描述问题`
- `未找到输入目标，未执行粘贴`
- `本地预览地址已打开`
- `配置已保存，正在等待按键服务生效`

禁止：

- `转写完成`
- `AI 已收到`
- `测试已通过`（没有真实回执时）
- `开发服务器已启动`
- `Workflow Runner completed`

错误文案顺序：发生了什么 → 未执行什么 → 可能原因 → 本次影响 → 立即修复 → 重新检测 → 技术错误码。

## 15. 视觉验收记录格式

每个 UI 阶段在 `docs/V2_0_PROGRESS.md` 记录：构建产物路径、启动参数、Computer Use 任务、实际可见状态、焦点结果、取消/错误恢复、DPI/分辨率/主题、截图路径和未验证项。源码检查不能替代实际 UI 记录。
