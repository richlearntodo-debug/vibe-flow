# V2.0 候选版已知限制

> **范围提示（2026-09-08 起）：** 本文件只描述当前 Host 的限制。Notes Deck/便签属于历史归档，不是候选安装包功能；未验证项目不能写成通过。

- 当前候选包未配置商业 Authenticode 签名。只应从项目所有者提供的候选渠道取得，并核对 `SHA256SUMS.txt`；产品不会引导绕过 Windows 安全警告。
- 未安装签名设备过滤器时，RC003 语音键（F5）采用“遥控器在线范围内”的钩子隔离（实测本机输入栈中钩子先于 Raw Input 且钩子抑制会取消对应 Raw Input，用户态无法做逐事件设备归属）。该隔离只在 RC003 已连接时拦截 F5：录音键不会再触发浏览器/页面刷新；遥控器不在线时普通键盘 F5 原样直通。仍不能与签名过滤器同日而语，100 次录音与普通键盘 F5 隔离真机矩阵未完成。
- Power、Back 和独立音量键：Power 键已实测可上报（vk 0xFF / scan 0x5E），但其按键同时会打开遥控器麦克风流，且与语音键重连变体相同，无法与“开机动作”安全区分；本机不映射、不改动 Windows 系统电源键行为。Back 与独立音量键无稳定事件，均不作为支持能力。
- 微信输入法的语音听写在本机以“剪贴板”方式给出识别文字（网页/Chromium 输入框与原生记事本均实测如此，不经过 Vibe Flow 单独使用同样行为），属第三方工具限制。Vibe Flow 在微信输入法链路的每次真实回执（提交回执或完整会话结束回执）后，会把文字自动粘贴回“唤醒时的前台应用”（或已验证的 Smart Focus 目标）：先按剪贴板公开序列号等待载荷落地并稳定（只观察计数器，不读取文字），等微信面板让出前台或把已验证目标窗口重新激活后，再注入一次 Ctrl+V；**不读取、不保存、不上传剪贴板文字，不自动回车、不自动发送，不把前台从无关应用抢走**。目标无法验证或用户已切走时不粘贴，并提示手动粘贴。默认语音工具保持微信输入法；Windows 语音输入仍可在语音页切换（可直写）。
- Smart Focus 只接受可验证编辑控件。应用 UI 更新后可能需要重新学习；未真机验证的应用不会标为“已验证”。**真机已确认**：记事本（`strategy=uia_focus`）与 ChatGPT 桌面端输入框都能被实时验证为可编辑控件（`VOICE INPUT TARGET ready=true code=OK`、`focused_edit=True` 连续三次采样），文字直接上屏且**剪贴板全程未被使用**。
- **被 `ApplicationFrameHost` 托管的经典 UWP 应用不作为输入目标支持**（这是决定，不是待办）：本机实测「设置」的可见顶层窗口属于 `ApplicationFrameHost.exe`、内容属于 `SystemSettings.exe`，而需要听写的应用（聊天、编辑器、终端、浏览器）都不属于这一类。学习这类应用是**失败即停**的：10 秒内没抓到可验证控件就记 `FAVORITE LEARN failed=true` 并**什么都不保存**，用户看到的是「没有学到输入框，请重试」而不是一个永远匹配不上的目标。
- Vibe Flow 不读取网页正文、第三方转写文字或剪贴板文本，也不自动发送 AI 消息。
- 配置保存后仍需 Bridge revision ACK；ACK 超时会保留警告，不虚报生效。
- Windows 10/11、125%/150%/200% DPI、VB-CABLE 重启恢复、全新/升级/卸载生命周期仍未完成授权环境验证；VB-CABLE 安装向导的“全新安装”路径需在无 VB-CABLE 环境复测。
- 重新打开首次设置并走第 4 步“选择工具并完成听写”时，点击“聚焦输入框并测试”会保存语音设置并重启语音桥接，桥接重启后会话代数（generation）从 1 重新计数；若本机已有历史会话，向导的听写基线可能高于新代数，导致“我已看到文字”被拒（提示“尚未取得本次真实音频与工具回执”）。处理：点“上一步”再点“完成本步，继续”重新进入本步以刷新基线，然后重新完成一次真实听写（3–5 秒）。
- **豆包输入法自 V2.0 起不再作为可选语音工具**（界面与文档均已移除该项）：实测（本机 v0.9.0.0）它的安全过滤会忽略全部模拟输入（`keybd_event`、`SendInput` 硬件扫描码、模拟鼠标点击均无效，中/英切换等状态按钮同样不响应），只有真实键盘按键有效，且语音面板只采集它自己选定的麦克风，不存在可用的自动路径。**旧配置的迁移**：V1.5 里选择过豆包的配置会在加载时被明确迁移到微信输入法（同时改回微信输入法的 `Ctrl + Win`、单击切换与 80 ms 参数），并弹出一次性提示、写入 `PROVIDER MIGRATED retired=doubao` 日志；不会静默按另一个工具运行。历史取证与逆向结论保留在 `docs/V2_0_TECH_MOAT_RESEARCH_ZH.md`，需要豆包时仍可手动用它自己的快捷键，或用「其他语音工具」把它当作自定义快捷键工具（自动唤起不可保证）。语音工具现状：**微信输入法（受控回填，已验证）、Typeless（按住快捷键）、Windows 语音输入（Win+H 直写，已验证）**，以及自定义工具。

- 免驱动模式（未检测到 VB-CABLE 时自动进入，也可用诊断开关 `VIBE_FLOW_TRIGGER_ONLY=1` 强制验证）：遥控器只当**无线触发器**，按键由后台桥接转成语音工具的快捷键，声音由**电脑麦克风**采集。该模式下不启动录音捕获进程（冻结内核在没有 `CABLE Input` 时必然启动失败），因此：不采集遥控器音频、不做默认录音设备的切换、Voice HUD 的“真实音频”证据不可用，自检的“遥控器麦克风真实音频 / RC003 配对 / 唤起链路”会明确标为“不支持”或“需要配置”而不是假装通过；Host 能自行唤起的工具目前只有 **Windows 语音输入（Win+H）与 Typeless**，微信输入法需要安装 VB-CABLE 回到完整模式。**本机尚未在没有 VB-CABLE 的真实环境按下遥控器验证过该链路（NOT_RUN）**，当前证据只覆盖“不启动注定失败的捕获、桥接继续工作、界面与日志如实标注”这三点。

- 首页与语音页会按当前模式如实显示：免驱动模式下首页标题为“免驱动模式已就绪 / TRIGGER ONLY”、状态条把“遥控器麦克风”换成“遥控器按键”，语音页的自动路由复选框显示为不可勾选的免驱动说明；这些显示不写入配置，安装 VB-CABLE 后自动回到完整模式语义。

- **设备类别“可见性修复”已改为显式确认的实验性动作，不再自动执行。** 原因：2026-09-10 本机在验证过程中发现 `CABLE Output`（虚拟声卡录音端）从 Core Audio 与注册表中整体消失（`SWD\MMDEVAPI` 设备不存在、`MMDevices\Audio\Capture` 无该端点，播放端 `CABLE Input` 仍正常，驱动设备 `ROOT\MEDIA\0000` 状态 OK），而在此之前 4 次端点属性写入均写入成功且可复读。**无法排除该实验性属性写入是诱因**（微软明确不保证应用写端点属性）。因此：启动时只读取类别并提示，写入必须由用户在“自检 → VB-CABLE 本地音频通道 → 优化可见性”里确认执行，写入后会立即复读校验，失败时给出“重新安装 VB-CABLE”的修复路径；默认不写、不还原、不改配置。若该端点消失，语音输入法将录不到遥控器音频（声音会退回电脑麦克风），此时应用会自动进入上述免驱动模式，不再假装录音。
- **虚拟声卡端点丢失后的恢复办法（本机实测，2026-09-10）**：运行内置官方驱动包即可重新创建驱动设备与两端点，本机实测**无需重启**——`scripts\Install-VBCable.ps1 -Install`（先校验固定 SHA-256，再执行 `VBCABLE_Setup_x64.exe /install`，需要 UAC 确认）。**不要尝试用“禁用/启用设备”恢复**：本机实测对 `ROOT\MEDIA\0000` 执行 `Disable-PnpDevice`/`Enable-PnpDevice` 后，VB-Audio 设备实例被整体摘掉（播放端也一起消失），重启也没有回来，最终仍靠官方安装包重新创建。重装后端点 GUID 会变化（本机 `c616f7cc…` → `4c48ae83…`），设备类别回到 Windows 默认的线路设备，因此需要重新执行一次“优化可见性”才能让只列麦克风的输入法看到它。非管理员无法完成恢复（`pnputil /scan-devices` 返回 Access denied）。

- **收音质量与“文字被替换/收回”的实测结论（2026-09-10，本机真实会话）**：主机侧回填**没有触发**（两次会话均 `WETYPE PASTE FALLBACK skipped=true reason=payload_missing`），所以“文字被收回”不是言灵的粘贴造成的，而是微信输入法自己的语音面板行为。同时内核日志显示：面板响应慢时会被**重复激发**（`WETYPE TOOLBAR CLICK`/`WETYPE HOTKEY TAP` 的 start 与 submit 各多次，某次 `trigger_to_ready_ms=1238` 触发了重试），面板被启动或提交两次就可能替换/收回已出现的文字。言灵现在会统计每次会话的激发次数，超过一次时提示“如果文字出现后被替换或收回，可改用 Windows 语音输入（直写上屏），或在微信输入法里把语音模式改为直接上屏并关闭 AI 整理”，并记录 `PANEL STIMULUS start=… submit=…`。收音质量方面：实测 `CABLE Output` 音量 100%、未静音、格式 48 kHz/2ch，端点层无异常；但会话指标显示**遥控器输入电平偏低**（`raw_rms_pct` 约 1.5–3.5%，内核自动增益 3–6 倍；同一支遥控器贴近说话的那次为 5.7%）且**蓝牙间隔经常超阈值**（近几次会话 164–465 ms，偶发 900+ ms，健康基线 ≤ 250 ms）。这两项决定识别质量：请把遥控器靠近嘴部说话、保持与电脑 5 米内并减少遮挡，必要时更换电池；言灵会在“自检 → VB-CABLE 本地音频通道”显示录音端音量，并在音量被重置（如重装驱动后）时提供一键“恢复 CABLE 音量”。

- **蓝牙音频断流的根因与修复（2026-09-10 本机实测确认）**：Windows 的 **USB 选择性挂起**会在空闲时挂起蓝牙适配器，导致遥控器 ATVV 音频出现 **271–537 ms 的块状断流**，语音工具收到的是缺块的音频，转译结果因此变成噪声（实测“hello vibe coding test”被识别成 “BERTThe batch”）。禁用后同一批测试的断流降到 **74–164 ms**、丢包 0、链路判定全部 `HEALTHY`（`link-baseline.json` 记录的 `over_250ms=0`），收音与转译恢复正常。本机 Windows **在电源选项里根本没有这一项**（`PowerSettings\{2a737441…}\{48e6b7a6…}` 定义键缺失），因此自检的「Windows 蓝牙」项会检测该值并在启用时提供**一键「禁用 USB 选择性挂起」**（`scripts\Set-UsbSelectiveSuspend.ps1`，需 UAC）；禁用后同一项会提供**「还原 USB 选择性挂起」**，而且只在脚本自己的 `state.json` 记录「本次禁用是本应用应用的」时才显示——如果 0 是公司镜像或你自己调出来的，不会劝你改回去。禁用属于电源策略调整，不影响音频链路、增益与冻结内核。

- **界面显示异常（乱码 / 挤在一起 / 字太小）怎么反馈**：自检页的「导出诊断」会把**界面实际使用的字体**与**屏幕环境**一起写进诊断文件，日志里也有一行 `UI RENDER`：
  `text_font=… text_installed=… icon_font=… icon_installed=… screen=WxH workarea=WxH dpi=… scale=… monitors=… window=WxH`。
  请把这一行（或整份诊断）一起反馈。判读方式：`icon_installed=no` 表示本机缺少界面图标字体（画面会变成一排方框）；`scale` 明显大于 1.00 且 `screen` 较小，说明是缩放/小屏下的布局问题；两者都正常而画面仍异常，才需要按视觉问题继续查。
- 界面图标来自**私有使用区字形**（`\uEAxx` 段），只有专门的图标字体才有：缺失时系统不会像中文那样做字体链接，因此会渲染成方框。已实测并加了自动挑字体 + 诊断上报；但**如果一台机器上连候选字体都没有，界面目前不会退化成"不用图标"的版本**（这属于已知缺口，尚未实现）。

V2 功能未配置或关闭时，不启动新后台工作，不自动改变旧映射、Profile 或 Smart Profile 状态。
