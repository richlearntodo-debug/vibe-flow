## 本次亮点

### 1. 单击开始，再次单击结束

- 新安装默认使用连续听写，不需要一直按住遥控器。
- 首次物理流结束后，主机自动建立真实 ATVV 音频流。
- 页面只有收到真实音频包后才显示“正在听写”；恢复空档和失败状态明确区分。
- 单次设置 `30 分钟`安全保护，避免忘记结束导致后台长期占用。

### 2. 长时音频链路完成真机验证

| 回归 | 真实音频覆盖 | 续租 | 丢包 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 124 秒 | `97.2%` | `15/15` | `0` | 通过 |
| 6 分钟 | `99.1%` | `45/45` | `0` | 通过 |
| 15 分 22 秒 | `99.6%` | `114/114` | `0` | 通过 |

最长回归中 WASAPI 与 VB-CABLE 端点全程正常，内存稳定在约 `49-51 MB`，没有音频停滞、传输失败或第二个麦克风。

### 3. 自检识别“计时正常但没有真实声音”

- 自检显示逻辑时长、真实音频时长和覆盖率。
- 汇总整场会话的最大蓝牙间隔、队列丢包、输出电平和 `MIC_EXTEND` 次数。
- 少于 `0.7 秒`的误触会话会提示重新测试，不再被计为完整通过。
- 持续会话检测到音频停滞时执行一次有界恢复；恢复失败会真实停止并给出下一步。
- 日志增加 WASAPI 状态、端点状态、路由所有者和内存采样，便于 GitHub Issue 排查。

### 4. 原生直填与稳定参数保持不变

- 微信输入法仍使用 `Ctrl + Win + Shift` AI 整理档案。
- 音频排空后再结束转写工具，避免句尾被截断。
- 不读取或修改剪贴板，不发送 `Ctrl + V`，文字由转写工具直接写入原输入框。
- 增益 `1.0x`、清晰增强、`180 ms`排空、`180 ms`工具启动等待和自动 `CABLE Output` 路由保持不变。
- 结束时仍只播放一次已验证的短提示音。

### 5. 按住模式仍可使用

习惯按下说话、松开结束的用户可在“语音听写”切换到按住模式。该路径完成独立回归：松开后 `80 ms` 内自然停止、不发送主机续流、不自动重开麦克风、原生直填和路由恢复正常。

RC003 一次物理长按仍有约 60 秒固件边界，因此长内容推荐连续听写。

### 6. 更新检查更可靠

- GitHub Release 元数据明确按 UTF-8 解码，中文发布说明不会导致解析失败。
- API 网络或元数据解析失败时，使用 GitHub 官方 `releases/latest` 重定向兜底。
- 安装前仍强制核对 `SHA256SUMS.txt`，并始终由用户确认。

## 日常操作

1. 点击目标输入框。
2. 单击录音键并松开。
3. 等待首页显示“遥控器音频正在到达”，自然说话。
4. 完成后再次单击录音键。
5. 听到结束音，等待文字直接进入原输入框。

## 升级说明

安装版直接覆盖安装。免安装版解压到新目录后运行 `VibeFlow.exe`。

- 新安装默认连续听写。
- 升级不会覆盖现有 `vibe-mic-config.json`，旧用户已选择的录音模式、转写工具和快捷键保持不变。
- 希望使用长时听写的旧用户，可在“语音听写 -> 录音方式”选择“连续听写（推荐）”。
- 升级后运行一次“连接与自检”，再完成 75 秒以上实际听写。

## 已知边界

- 连续听写单次有 `30 分钟`软件安全保护，不宣传绝对无限时长。
- 第一次物理流切换到主机持续流时可能短暂显示“正在恢复遥控器音频”；看到“音频正在到达”后再开始长段口述。
- 按住模式受 RC003 约 60 秒物理长按上限约束。
- 转写工具可能有自己的账号、网络、识别或时长限制。
- RC003 独立返回键和音量 +/- 键在已验证 Windows 蓝牙栈中没有稳定事件。
- 功能组合键未通过稳定性验证，本版只宣传单键操作。
- 商业 Authenticode 签名取决于发布者是否配置证书；未签名文件应只从本仓库 Releases 下载并核对 SHA-256。
