# Windows 正式版发布质量门禁

本清单用于每个正式 Release。自动化通过不等于真机通过；未完成的项目必须在 Release 中明确标注。

## 自动化门禁

- [ ] `npm test` 通过，版本、默认配置、更新源与冻结 Capture 哈希一致；
- [ ] 在干净的 GitHub Windows runner 上完成依赖恢复和正式构建；
- [ ] 静默安装到空目录，检查 Host、Bridge 与冻结 Capture 文件；
- [ ] 从上一个推荐正式版升级，用户配置不丢失；
- [ ] 卸载完成，程序目录和自启动注册清理正确；
- [ ] EXE、ZIP 与 SHA-256 同批生成且可公开重新下载；
- [ ] 若为签名正式版，安装器、Host 与 Bridge 均通过 `signtool verify /pa /all`。

## 真机门禁

- [ ] Windows 10 x64 干净环境：安装、首次设置、升级、卸载；
- [ ] Windows 11 x64 干净环境：安装、首次设置、升级、卸载；
- [ ] 蓝牙晚启动、遥控器休眠/唤醒、断开/重连；
- [ ] Windows 睡眠/唤醒、锁屏/解锁；
- [ ] 100 次录音按下/松开，无重复会话；
- [ ] 10 秒、30 秒和约 60 秒真实音频转译；
- [ ] 微信输入法与至少一个其他语音工具完成端到端输入；
- [ ] 更新后设置、Profile 与快捷键映射保持一致。

## 不能由云端替代的验证

GitHub runner 没有 RC003、真实蓝牙栈、ATVV 麦克风、VB-CABLE 音频流和交互式语音工具，因此休眠恢复、真实音频覆盖与转译质量必须记录真机证据。没有证据时状态只能写“未验证”，不能写“通过”。
