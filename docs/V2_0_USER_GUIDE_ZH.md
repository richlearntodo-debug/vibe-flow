# 言灵 Vibe Flow Remote V2.0 候选版使用指南

> 当前状态：`2.0.0` candidate，尚未完成全部真机和安装生命周期验收。普通用户继续使用已发布的 V1.5.0；测试候选包前请先阅读[已知限制](V2_0_KNOWN_LIMITATIONS_ZH.md)。当前产品不包含便签本、Notes Deck 或便签 AI。

## 三分钟上手

只想先跑通一次听写，按这四步：

1. **配对遥控器**：设置里让 Windows 认到 `MI RC` / RC003，按一次方向键确认真的有事件进来（普通键盘做不到这一步）。
2. **选语音工具**：语音页选微信输入法 / Typeless / Windows 语音输入，并让两边的触发快捷键**完全一致**。
3. **打开目标应用**：在工作流页「添加应用」→ 按提示点一下它的输入框 → 学到后「保存」→「设为当前」。
4. **按住录音键说话，松开**，目视检查文字，再手动确认发送。

> 说完之后如果**文字不对或没进来**，先看语音页那行「**最近一次收音电平**」——低于 10% 就是声音太小，见下文[收音质量](#收音质量怎么看怎么调)。这条能解释大多数"时对时错"。

本指南其余部分按页展开：六个页面各做什么、文字怎么固定送进应用、按键怎么分层、以及出问题怎么查。

## 日常闭环

1. 打开或激活 ChatGPT 等目标 APP。
2. 在“语音”页选择并学习目标输入控件；保存前必须立即测试。暂未验证时，手动点击输入框并保持插入光标。
3. 按住原遥控器录音键说话，松开结束；录音结束只表示等待语音工具处理。
4. 用户目视检查文字，再按确认键手动发送。Vibe Flow 不读取、保存、回填或自动发送第三方转写文字，不自动发送消息。

## 六个页面

- **首页**：设备、语音桥接、Profile、工作流和最近真实回执；错误显示影响与修复入口。
- **工作流**：把文字固定送进常用应用——添加、学习、保存，之后每个应用都有明确状态和可做的事。
- **快捷键**：保留 V1.5 映射与 Profiles，并新增「短按 / 长按 / 双击」三层手势；每一层都能单独绑定动作，没有单独配置的层会**跟随**上一层并在卡片上写明跟随的是哪一层。录音键固定走稳定语音链路，不参与自定义映射，也不参与手势分层。
- **语音**：显示 `hold` 触发方式、音频端点、语音工具和工作流状态；高级冻结参数不作为普通编辑项。
- **自检**：检查组件、蓝牙、真实音频、VB-CABLE、语音工具、按键过滤器和会话，并提供重新检测。
- **设置**：外观、后台启动、托盘、隐私、本地数据、更新和诊断重置。

**反馈只会出现在一个地方**：你正在看言灵窗口时，结果留在窗口内右下角的卡片里；窗口不在前台、最小化或收进托盘时，才由浮动的状态浮层（Live HUD，屏幕右下角，不抢焦点）来告诉你。同一条结果不会同时出现两次。如果你想主动看一眼状态浮层，右键托盘图标选「显示 Live HUD」，这时它是额外的，不会顶掉窗口内的卡片。

## 工作流：把文字固定送进常用应用

在「工作流」页：**添加应用 → 按提示点一下那个应用的输入框 → 学到后点「保存」**。保存之后每个应用都有明确的状态和可做的事。

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 还没学习过 | 只添加了应用，还没学输入框 | 点「学习」 |
| 已学习但未验证 | 学到过，但还没做过一次真实测试 | 点「编辑」里的「测试焦点」确认 |
| 已验证 | 输入框可用 | 点「设为当前」，文字就会进入它 |
| 目标已失效 | 保存的输入框在当前数据里找不到了 | 点「重新学习」重新捕获 |

**「当前」只有一个**：按住录音键时，文字只会进入标着「✓ 当前」的那个应用。

**两种模式**（点应用名字下面的小胶囊切换，鼠标停在上面有说明）：

- **工作流**：可以被设为「当前」；说话前先把焦点恢复到它学到的输入框，文字固定送进它。
- **快捷键**：只在点「打开」时被召唤，**不会自动接走文字**。把它从工作流切回快捷键时，如果它原本是当前应用，会自动取消「当前」。

每行右边的「编辑」可以：改显示名称、切换模式、查看学到的输入框详情（策略 / 控件类型 / 上次验证时间）、**测试焦点**（不必重新学习就能确认输入框还能不能用）、以及直接「设为当前」。

### 终端、控制台和商店应用

- **终端 / 控制台窗口**（Windows Terminal、cmd 等）与**商店（UWP）应用**没有普通文本框那样的「可写入」输入区，它们被学成**焦点型目标**：Vibe Flow 负责把焦点放回去，文字由语音工具打进当前焦点。这类目标以前会在学完之后一直显示「目标已失效」，说话时文字送不进去——已修复，现在记事本、终端这类窗口保存后就能正常接字。
- **商店应用可以在没运行时直接添加**：选中后会自动打开，启动后按真实进程名记录（不是包的标识符），之后每次都会正确找到它，而不是重复启动。列表里商店应用现在也有自己的图标。
- **带参数启动的应用**：如果应用**已经在运行**，Windows 只会激活已经打开的那个窗口，不会把保存的命令行参数再应用一遍——这是单实例应用的固有行为。遇到这种情况会记一条 `FAVORITE APP AUTOSTART reused=true arguments_applied=false` 而不是假装启动成功。
- 首页的「工作流」入口现在**不用滚动就能看到**（原先在首屏之下，必须滚动到底部才能找到）。

## 手势分层（快捷键页）

每个可配置实体键都有三行，各自绑定**一个**动作：**短按 / 长按（按住约 0.65 秒）/ 双击（按一下、松开，再按一下；两下的间隔跟随你 Windows 的双击速度设置，下限 500 毫秒）**。

- 某一层没单独配置时，会先跟随上一层（双击 → 长按 → 短按），卡片上会写明跟随的是哪一层；
- 每一层右边的「▶」是测试按钮，不用真按遥控器就能确认这一层会执行什么；
- 录音键固定在稳定语音链路，**不参与手势分层**。
- **卡片按实体遥控器排布**：左列卡片、中间是遥控器图形与手势说明、右列卡片；最上面一行就是遥控器顶部的两个键——**左边开机键，右边录音键**。
- **电源键可以配置了**（Windows 上报为 `VK 0xFF` / 扫描码 `E0 5E`）：未指派动作时它仍交给 Windows（实测轻触无系统动作），指派后才由言灵拦截并执行。**一个需要知道的取舍**：同一个扫描码也是**蓝牙重连后麦克风键**的形态，所以一旦你给电源键指派了动作，重连后那一次麦克风键也可能被当成电源键。如果更看重录音可靠，就把电源键设成「不执行动作」。

**首次安装自带一套推荐手势**，不用自己一格一格配：长按 上/下 翻页、左 返回上一页、右 重做、确认键静音；双击 上/下/左/右 是剪切 / 全选 / 撤销 / 保存，确认键播放-暂停，功能键音量 +，TV 键音量 −，TV 长按打开 ChatGPT。这套推荐表**只在一台还没有手势表的机器上写入一次**：你自己改过之后不会再被覆盖，全部清空也不会自动恢复。

- **Home 键不在推荐表里**，这是有意的：它的短按是「显示桌面」，而双击的第一下会先执行短按，于是桌面先被显示出来，第二下就很难在双击窗口内按出来（真机实测第二下晚了 2235 毫秒）。如果你愿意把 Home 短按换成一个无害动作，双击 Home 就能正常用。

**一个需要知道的取舍**：双击需要判断「你是松开了，还是又按了一下」，所以一个键只要绑了双击，它的**短按就会变成松手时触发**（原来是按下去就触发）。不想要这个变化，把该键的双击设成「不执行动作」即可。

## 首次设置五项任务

1. **了解流程与隐私**：按住说话、松开结束、等待语音工具处理、目视检查、手动确认。
2. **连接并验证遥控器**：配对 `MI RC` / RC003，并用真实方向键确认设备事件。
3. **准备本地音频通道**：检查 RC003 ATVV、`CABLE Input` 和 `CABLE Output`；VB-CABLE 安装需要用户确认。
4. **选择语音工具并真实听写**：设置微信输入法、Typeless、Windows 语音输入或自定义工具；最终文字由用户目视确认。
5. **完成个性化**：选择后台启动、托盘和 Smart Profiles；添加常用应用可稍后完成。

进度会保存。必要条件未验证时可以稍后处理，但完成页会继续显示影响；快捷键配置落盘后还要等待 Bridge revision ACK，才会显示按键服务已生效。

## Smart Focus 工作流

- 先选择目标应用，再学习可编辑、可获得键盘焦点的 UI Automation 控件。
- 保存前必须“立即测试”。描述符只保存进程名、AutomationId、控件类型、类名和稳定父级指纹，不保存控件文字、窗口标题正文或屏幕坐标。
- 目标失效、进程不匹配或录音开始时，操作安全停止，不发送按键。
- 未验证应用只提供激活应用、用户测试过的聚焦快捷键或手动点击回退。

## 收音质量：怎么看、怎么调

转写时对时错、或者干脆没收到内容，**多数时候不是识别的问题，而是送进去的声音太小**。语音页现在会显示**最近一次收音的实测电平**，你不用猜：

- **「最近一次收音电平 X%（偏低，识别舒适区约 10–30%）」**（琥珀色）：声音偏小。按顺序做四件事——
  1. **距离与朝向**：遥控器离嘴 **10–20 厘米**，对准**遥控器顶部的麦克风孔**；
  2. **Windows 输入电平**：设置 → 系统 → 声音 → **输入** → `CABLE Output` → 属性 → **级别**：输入音量拉到 **100%**，有「麦克风加强」就打开；
  3. **换一节新电池**：电量低会直接压低遥控器麦克风的增益；
  4. **握稳、别摩擦遥控器**：实测约三分之一偏低的会话是「碰触噪声」而不是人声。
- **「X% · 处于识别舒适的区间」**（绿色）：电平没问题，若仍识别不佳，请检查语音工具本身的设置或网络。
- **「这一次没有收到音频」**（红色）：这一次完全没有音频帧——确认遥控器已连接并被唤醒，再试一次。
- **「还没有记录」**：还没完成过听写，说一次之后这里就会有数字。

想看得更细，可以在命令行运行仓库里的只读诊断脚本，它会列出最近若干次会话的电平、增益、链路断档与判定：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\tests\Get-CaptureLevels.ps1 -Last 15
```

**为什么软件这边帮不上更多**：言灵已经在自动放大（实测约 4 倍），而且大约三分之一的会话峰值已经打满（再加大增益只会连带放大底噪与失真）。所以这一项**只能从声源侧解决**——也就是上面四步。采集内核与语音参数属于冻结的稳定档，不会为了这个被改动。

## 录音与剪贴板边界

- 录音始终是按住开始、松开结束；Capture 继续使用冻结参数和约 60 秒设备边界。
- Vibe Flow 不自研识别，不读取或保存第三方转写文字，也不把转写文字写入或从剪贴板回填到输入框。
- 唯一的例外是**用户自己填写的用语片段**：文字由用户自备、只保存在本机 `UserData\snippets.json`，按下绑定的按键时按字符直接写入当前输入框，不经过剪贴板；言灵不会读取、比对或记录这些文字的内容（日志只记长度）。
- 截图、自动发送、任意脚本和后台工作流不属于当前主导航；用户需要发送时必须自己检查并按确认键。

## 遇到问题

先打开「自检」，从第一个警告或错误开始处理。每项都会显示：发生了什么、本次未执行什么、可能原因、修复入口、重新检测和错误码。

| 你遇到的现象 | 先做什么 |
| --- | --- |
| **转译时对时错、或没收到内容** | 看语音页那行「**最近一次收音电平**」：低于 10% 就按[收音质量](#收音质量怎么看怎么调)那四步处理（距离与朝向、Windows 输入电平、电池、握稳）。这是最常见成因，而且能自己看出来 |
| 说完之后文字**没有进入输入框** | 工作流页确认目标是不是「✓ 当前」；再看它的状态是不是「已验证」；必要时用「编辑 → 测试焦点」重新确认 |
| **麦克风或快捷键无响应** `[VOICE-RUNTIME-INCOMPLETE]` | 确认运行目录同时存在 `VibeFlow.exe`、`VoxDeckInputBridge.exe`、冻结的 `VibeMicAtvvCapture.exe`、`NAudio.Core.dll`、`NAudio.Wasapi.dll` |
| **实体键盘的 F5 被拦了** | 这是"遥控器在线范围"隔离的已知副作用（见[录音键隔离](#录音与剪贴板边界)），遥控器断开会自动恢复；彻底按设备隔离需要签名过滤器，当前候选不含该驱动 |
| **返回键 / 独立音量键没反应** | 预期行为：这两个键没有稳定的 Windows 事件，不作为支持按键（不作为映射项） |
| **文字进了剪贴板历史** | 只有用语片段是逐字符注入、不经过剪贴板的；微信输入法链路由其自身把文字放进剪贴板，言灵只在焦点已验证时投递一次粘贴 |

诊断日志不保存普通录音、转写文字、截图内容或完整窗口标题。提交问题时请附**错误码、版本和去敏日志**，不要上传私人截图。
