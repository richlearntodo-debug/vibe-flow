## 本次亮点

### 1. 按住开始，松开结束

- 按下与松开由独立事件处理，松开后不会再次打开麦克风。
- 首页实时显示录音状态、计时、遥控器麦克风光效和结束提示。
- 新安装和 schema 18 升级默认使用按住说话。

### 2. 明确 60 秒硬件边界

- RC003 持续长按约 60 秒会主动发送 `F5 UP` 与 ATVV 停止。
- `MIC_OPEN`、`MIC_EXTEND` 和会话重开不能在该按压内恢复真实音频。
- 稳定模式不会在松开或固件停止后自动重开，避免第二个麦克风。
- 连续听写仅保留为“短按后立即松开”的实验选项，并保留 10 分钟故障安全保护。

### 3. 更清晰的状态反馈

- 首页突出“按住开始、松开结束”的稳定操作路径。
- 最近听写显示单次音频时长和输出电平；实验连续模式仍可显示逻辑总时长与分段数。
- 紫色表示收音、青色表示整理、绿色表示完成、红色表示异常。
- 录音开始保持安静并使用首页波纹光效，结束时播放清晰、短促的完成音；不会因 60 秒物理分段重复播放。
- 完成状态使用绿色视觉反馈，不再叠加第二个声音；失败仍有独立告警音。所有声音反馈均可关闭。
- 微信听写开始前会临时关闭 Windows“通信活动”自动降音，结束后恢复用户原来的系统偏好；异常退出由恢复标记兜底。

### 4. 文字直接返回原输入框

- Windows UI Automation 会持续保留最近一次有效编辑控件；开始听写时依次检查当前焦点、鼠标所在输入框和同一程序内最近的输入框。
- 可聚焦的网页 `Group` 容器不会再被误判为文字输入目标。
- 微信输入法默认使用已经真机验证的 AI 整理档案：音频路由就绪后轻触 `Ctrl + Win + Shift` 开始，排空最后一段声音后再次轻触结束。
- 结束顺序固定为“排空 VB-CABLE -> 停止微信听写 -> 等待 350 ms -> 恢复原麦克风”，避免句尾被提前切断。
- 不点击微信工具栏或状态栏入口，避免进入“已复制文本”的剪贴板交付模式。
- 录音期间只被动确认原输入框仍保持焦点，不再激活窗口或调用 UI Automation `SetFocus`，避免破坏微信输入法的原生文字上下文。
- 微信路径不监听或修改剪贴板，也不会发送 `Ctrl + V`；文字由微信输入法直接写入原输入框。
- “连接与自检”会明确显示原生直填是否具备条件。

结束音由录音状态切换直接触发，不再等待页面每 500 ms 读取一次日志，因此不会因捕获进程重连造成漏播或延后。

### 5. 安全更新与发布签名

- “偏好设置”可自动或手动检查 GitHub 最新正式版。
- GitHub API 达到限额时自动使用官方 `releases/latest` 重定向，不影响普通更新。
- 安装包必须与 `SHA256SUMS.txt` 一致，校验后仍需用户确认才会安装。
- 发布脚本支持 Authenticode 证书指纹或 PFX，先签应用组件，再签安装包并强制验签。

## 升级说明

安装版直接覆盖安装。免安装版解压到新目录后运行 `VibeFlow.exe`。

程序不会覆盖已有 `vibe-mic-config.json`。升级后：

1. 在“偏好设置”确认版本为 `1.1.0`。
2. 在“语音听写”确认录音方式为“按住说话”。
3. 在“连接与自检”确认 7/7 通过。
4. 按住完成一次 8 到 10 秒实际听写，松开后确认不会出现第二个麦克风。

## 已知边界

- 稳定按住模式受 RC003 约 60 秒物理长按上限约束。
- 实验连续听写有 10 分钟安全保护。
- 转写工具可能有自身时长、网络或账号限制。
- RC003 独立返回键和音量 +/- 键在已验证 Windows 蓝牙栈中没有稳定事件。
- 功能键组合操作未通过稳定性验证，本版只保留单键操作。
- 商业 Authenticode 签名仍取决于发布者是否配置证书；未签名文件必须只从本仓库 Releases 下载并核对 SHA-256。
