# RC003 返回键与独立音量键研究记录

日期：2026-08-23

## 目标

让小米 RC003 / MI RC 遥控器的物理返回键、音量加键和音量减键在 Windows 上稳定进入言灵的按键映射层，同时不影响已经验证可用的录音、方向、确认、Home、TV 和功能键。

## 已确认事实

- RC003 在本机创建了一个 Bluetooth LE HID 键盘集合：Generic Desktop / Keyboard（Usage Page `0x01`，Usage `0x06`）。
- Windows 没有为它创建 Consumer Control 集合。
- 键盘钩子、Keyboard Raw Input 和 Consumer Raw Input 均收不到三个目标物理键。
- 同型号公开实现将目标 Usage 标记为：返回 `0xF1`、音量加 `0x80`、音量减 `0x81`；这些值不能代替本机事件链验证。

## 实测路径

### 1. Windows 标准输入通道

低层键盘钩子、设备限定 Raw Input、Consumer HID Usage 解析均已验证。普通方向、确认、Home、TV、功能键可见，返回和独立音量键不可见。

结论：不是快捷键映射遗漏，事件在到达应用前已经丢失。

### 2. 直接读取 HID GATT 服务

服务 `00001812-0000-1000-8000-00805f9b34fb` 可以枚举，但读取其 Characteristics 返回 `AccessDenied`。这是 Windows 对系统托管 HID 服务的访问边界。

结论：普通用户态 WinRT 应用不能直接订阅 HID Report 特征。

### 3. 厂商自定义 GATT 服务

服务 `8a7a0001-2c42-c2a2-0f36-41928c259b78` 暴露三个可订阅 Notify 特征。三者均成功启用通知，但按 Home、返回、音量加、音量减时没有任何通知。公开资料中也没有找到可信的握手协议；不能通过猜测写命令激活。

结论：没有证据表明该服务是可直接使用的按键通道。

### 4. WUDFHost HidOverGatt 只读旁路

使用固定 SHA-256 的 Frida Gadget，仅向注册表确认的 RC003 `WUDFHost.exe` 注入，并监听参考实现使用的 `NtDeviceIoControlFile` / IOCTL `0x80018483`。注入、目标校验、本机回环连接和 Hook Ready 均成功。

随后执行了：

- Home、返回、音量加、音量减逐键测试；
- RC003 HID 设备节点原生 `restart-device`；
- Hook 就绪后再次逐键测试；
- 只记录 IOCTL 编号、状态和缓冲区长度的诊断。

没有捕获到 HID 报告，也没有观察到按键期间的新目标 IOCTL。本机的 `WUDFHost` 还同时承载另一台 BLE HID 设备，因此不能通过终止共享宿主进程继续试验。

结论：参考旁路不适用于本机 Windows 蓝牙驱动实现，不能作为正式功能发布。进程显示 Ready 不等于物理按键链路可用。

## 发布结论

当前正式版本不宣称支持 RC003 的物理返回键和独立音量键，也不包含实验注入组件。继续保留已经真机验证的备用操作：短按方向键保持导航，长按上/下调节系统音量。

要正式支持三个物理键，下一阶段应开发并签名一个作用于 RC003 HID-over-GATT 设备栈的专用过滤驱动，在 Windows 丢弃非标准 Usage 之前读取报告。该方案需要：

1. KMDF/UMDF HID 过滤层原型和设备范围限定；
2. Windows 10/11 多版本及蓝牙适配器兼容测试；
3. 睡眠、重连、升级和卸载测试；
4. 驱动签名与发布流程；
5. 独立威胁模型和代码审查。

在签名驱动完成真实硬件验收前，不应在 UI 中展示返回键和独立音量键为可用功能。
