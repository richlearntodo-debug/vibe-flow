# 录音模式：稳定边界与验证基线

适用于言灵 Vibe Flow Remote `v1.2.0`。

## 推荐：连续听写

连续听写适合长提示词、会议记录和 Vibe Coding 口述：

1. 聚焦要输入文字的文本框。
2. 单击 RC003 录音键并松开。
3. 等待首页显示“遥控器音频正在到达”，再自然说话。
4. 完成后再次单击录音键。
5. 听到结束提示音，等待转写工具把文字直接写回原输入框。

用户不需要持续按住录音键。新安装默认使用该模式，单次会话有 `30 分钟`安全保护。该上限用于防止忘记结束导致后台长期占用，不代表所选转写工具一定支持相同时长。

## 为什么可以超过 60 秒

RC003 的实体录音流使用 `start_reason=0x03`，松键后会自然停止。言灵保留同一个逻辑听写会话，并由主机建立新的 ATVV 音频流：

```text
单击录音键
  -> RC003 实体音频流开始
  -> 松键后实体流自然停止
  -> 主机建立 start_reason=0x00 的持续音频流
  -> 每 8 秒向当前精确 session 发送 MIC_EXTEND 0x0E
  -> 再次单击后精确关闭当前流
  -> 排空 VB-CABLE
  -> 结束一次转写工具会话
```

第一次主机打开有时只建立控制状态，因此实现会进行有界重试，并且只有收到真实 `AUDIO LIVE START` 后才把页面标记为正在听写。恢复空档显示青色“正在恢复遥控器音频”，失败则停止会话并在自检中标红，不会用逻辑计时伪装成真实收音。

## 真机验证记录

测试设备为 RC003、Windows 10/11 音频栈、VB-CABLE 与微信输入法 AI 整理模式。

| 会话 | 逻辑时长 | 真实音频 | 覆盖率 | MIC_EXTEND | 丢包 | 最大包间隔 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 124 秒基线 | `127.6 s` | `124.1 s` | `97.2%` | `15/15` | `0` | `60 ms` |
| 6 分钟回归 | `382.3 s` | `378.8 s` | `99.1%` | `45/45` | `0` | `61 ms` |
| 15 分 22 秒回归 | `921.8 s` | `918.2 s` | `99.6%` | `114/114` | `0` | `75 ms` |

最长回归中：

- WASAPI 始终为 `Playing`，VB-CABLE 端点始终为 `Active`。
- 蓝牙解码队列和 VB-CABLE 输出队列丢包均为 `0`。
- 未出现 `AUDIO TRANSPORT STALLED` 或 `AUDIO TRANSPORT FAILED`。
- 私有内存稳定在约 `49-51 MB`，没有持续增长。
- 结束时原输入框为可写状态，交付方式为 `provider_direct`。
- 停止后没有自动出现第二个转写麦克风。

这些数据是当前发布参数的回归基线，不应被解释为所有蓝牙适配器、遥控器固件或第三方转写工具都能达到完全相同的时长。

## 兼容：按住说话

按住模式仍保留给习惯“按下说话、松开结束”的用户：

1. 按住录音键开始。
2. 保持按住并说话。
3. 松开后结束。

真机回归确认松开后 `80 ms` 内收到自然停止，只启动一个转写会话，不发送 `MIC_EXTEND`，文字直接写回且麦克风路由正常恢复。

RC003 固件会在一次物理长按约 60 秒时主动发送 `F5 UP` 与 ATVV `stream_stop`。因此按住模式单次仍以约 60 秒为硬件边界；更长内容应使用连续听写。这不是微信输入法、Typeless 或 VB-CABLE 的限制。

## 推荐验收

连续模式：

1. 确认“录音方式”为“连续听写（推荐）”。
2. 单击开始并松开，等待紫色“遥控器音频正在到达”。
3. 说话 75 秒以上，中间停顿 10 秒。
4. 再次单击结束，确认只播放一次结束音。
5. 确认文字直接进入原输入框，自检显示音频覆盖率、零丢包和麦克风已恢复。

按住模式：

1. 切换为“按住说话（兼容）”。
2. 按住 8 到 10 秒后松开。
3. 等待 5 秒，确认麦克风不会自动重开。

## 发布稳定性约束

没有新的 RC003 真机回归前，不应修改：

- 连续听写状态机 `v2` 与 `30 分钟`安全保护。
- 主机音频流每 `8 秒`向精确 session 发送的 `MIC_EXTEND`。
- 增益 `1.0`、处理模式 `speech`、排空 `180 ms`。
- 微信输入法 `Ctrl + Win + Shift`、单击切换和 `180 ms`启动等待。
- 自动 `CABLE Output` 路由及结束后的原端点恢复。
- 按住模式 RELEASE 自然停止窗口 `260 ms` 与有界兜底。

当前稳定备份与回归日志应在修改上述参数前保留。
