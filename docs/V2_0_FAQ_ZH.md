# Vibe Flow V2.0 FAQ 与故障排查

> 本页回答候选版 `v2.0.0-candidate.3` 的高频问题。遇到问题时，先看[图文使用教程](V2_0_USER_GUIDE_ZH.md)，再按本页顺序排查。

## 下载和版本

### V2.0 到底在哪里下载？

V2.0 候选版 3 的固定入口是：

- [VibeFlow-Setup.exe](https://github.com/richlearntodo-debug/vibe-flow/releases/download/v2.0.0-candidate.3/VibeFlow-Setup.exe)
- [Vibe-Flow-Windows-x64.zip](https://github.com/richlearntodo-debug/vibe-flow/releases/download/v2.0.0-candidate.3/Vibe-Flow-Windows-x64.zip)
- [SHA256SUMS.txt](https://github.com/richlearntodo-debug/vibe-flow/releases/download/v2.0.0-candidate.3/SHA256SUMS.txt)

### V2.0 是正式稳定版吗？

不是。它是公开候选版，仍需在真实 RC003、VB-CABLE、Windows 10/11、不同 DPI 和安装升级环境中完成完整回归。需要稳定版本时使用 [V1.5.0](https://github.com/richlearntodo-debug/vibe-flow/releases/tag/v1.5.0)。

### 安装包为什么显示未知发布者？

当前安装包没有商业 Authenticode 签名。请核对 GitHub 下载地址和 `SHA256SUMS.txt`，不要关闭 SmartScreen 或通过非官方渠道获取文件。

## 录音和文字落点

### V2.0 支持哪些语音工具？

当前「语音」页提供三个选项：微信输入法（默认，`Ctrl + Win`）、网易八哥说（右 Alt）和其他语音工具（右 Shift）。讯飞语音输入法、搜狗输入法和豆包输入法都已不再集成，也不会出现在首次设置中。

Typeless 和 Windows 语音输入不再作为 V2.0 的可选语音工具；配置里保存的这些旧值（以及上面三个已移除工具的值）都会在加载时迁移为微信输入法，并显示一次迁移提示。

### 松开录音键会自动发送吗？

不会。松开只结束录音并等待语音工具处理。看到文字后由用户检查，再按确认键发送一次。

### 为什么文字进了剪贴板，没有进 ChatGPT？

先区分语音工具：

1. 微信输入法部分版本会把识别结果写入剪贴板，这是第三方工具行为，不代表 Vibe Flow 已经读取或保存了文字。
2. Vibe Flow 不保证微信输入法在所有 ChatGPT、浏览器和提权窗口中直写。
3. 如果候选版本收到真实完成回执且目标输入框仍验证为可写控件，可能派发一次 `Ctrl+V` 兼容粘贴；日志中的“动作已派发”不等于 AI 已收到。

如果仍停留在剪贴板：点击 ChatGPT 输入框确认光标，手动 `Ctrl+V` 只做一次；随后打开自检，记录语音工具、目标状态和错误码。不要让程序读取剪贴板文字回填。



### 录音键按住时窗口会刷新或光标丢失怎么办？

1. 检查遥控器是否在线，以及自检中的 RC003 设备级过滤器状态。
2. 如果过滤器不可用，RC003 的 F5 可能穿透到前台；这属于设备隔离限制，不能用全局键盘 Hook 或修改 Capture 绕过。
3. 先在手动点击输入框的路径下测试，再测试 Smart Focus。
4. 记录前台应用、是否刷新、`input-bridge-health.json` 和错误码。

## Smart Focus

### Smart Focus 只是打开应用吗？

不是。只有“应用已激活”不能算成功。Smart Focus 必须找到属于目标进程、具备编辑语义、能够取得键盘焦点并通过验证的控件，才会显示“已验证”。

### 为什么学习后仍然提示目标失效？

常见原因：

- 应用更新后 AutomationId 或控件结构变化；
- 目标应用已关闭或换成了另一个进程；
- 学到的是按钮、列表或只读区域，而不是编辑控件；
- 目标应用以更高权限运行，Vibe Flow 无法跨权限聚焦。

点击“重新学习”，在目标应用中直接点击真正输入框，再点“立即测试”。不要用固定屏幕坐标代替学习。

### 手动点击输入框和 Smart Focus 哪个优先？

用户刚刚手动点击的有效输入框优先。Smart Focus 用于恢复已经学习并验证过的目标；录音过程中不会打开窗口、弹出 Deck 或抢走焦点。

## VB-CABLE 和收音

### `CABLE Input` 和 `CABLE Output` 怎么选？

- Vibe Flow 播放端：`CABLE Input`；
- 语音工具的麦克风输入：`CABLE Output`。

方向选反时，遥控器可能显示已连接，但语音工具收不到声音。

### 为什么自检显示 VB-CABLE 已安装，录音仍失败？

“已安装”不等于“端点可用”。检查：

1. `CABLE Input` 和 `CABLE Output` 是否都存在；
2. `CABLE Output` 是否被静音或输入音量为 0；
3. 语音工具是否真的在听 `CABLE Output`；
4. 最近一次收音电平是否有数值；
5. 蓝牙是否断开或正在被耳机/音箱争用。

### 收音电平低于 10% 怎么办？

把遥控器靠近嘴部约 10–20 厘米，对准顶部麦克风孔，握稳并检查 `CABLE Output` 输入级别。不要为了补偿低电平修改冻结 `gain=1.0`；过度增益会放大底噪和削波。

## 快捷键和 Profiles

### 为什么快捷键保存了但没有生效？

保存配置不等于 Bridge 已经应用。等待页面显示 Bridge ACK；如果仍未生效：

1. 确认当前 Profile；
2. 确认你编辑的是正确实体键和手势层；
3. 确认没有运行第二个 Vibe Flow 实例；
4. 重新检测并查看自检错误码；
5. 必要时退出托盘并重新启动一次。

### 录音键能不能改成普通快捷键？

不能。录音键固定为按住/松开语音链路，不参与自定义映射、Smart Focus、HUD 或 Deck 动作。

### 电源键为什么不建议绑定动作？

当前 RC003/Windows 组合中，电源键扫描码可能与蓝牙重连后的麦克风键形态相同。绑定动作后，重连时可能把麦克风键识别为电源键。更重视录音可靠性时请保持“不执行动作”。

### 为什么配置了双击后短按变慢了？

系统需要等第二次按键来判断是否为双击，所以短按会在松手时触发。清空该键的双击动作即可恢复原来的按下即执行。

## HUD、Deck 和自检

### HUD 显示“录音已结束”是不是转写完成？

不是。它只表示 Capture 已结束本次收音，语音工具仍可能在处理。必须看到目标输入框中的文字并由用户检查。

### Context Deck 会不会执行第二次动作？

不会。Deck 是只读说明面板，遥控器动作仍由原有 Bridge 路径执行。

### 自检显示“成功”但我仍然不能输入，怎么办？

自检只对它实际能观察到的证据给出结论。先看具体项目：设备、音频、语音工具、目标输入框和 Bridge ACK 可能分别有不同状态。重新检测后再完成一次短句测试；不要把“设备已配对”当成“文字已进入输入框”。

## 升级、重启和数据

### 从 V1.5 升级会覆盖我的快捷键吗？

不应覆盖。V2.0 会保留语音工具、触发方式、Profiles、快捷键映射、主题、托盘和 Smart Profiles 状态。升级后仍应在快捷键和语音页核对，并运行自检。

### 睡眠或蓝牙重连后要做什么？

等待遥控器重新连接，确认方向键事件和音频端点，再完成一次 3–5 秒的真实听写。不要同时启动第二个 Bridge 或 Capture。

### 卸载会删除 VB-CABLE 吗？

不会自动移除其他软件可能使用的共享驱动。需要删除 VB-CABLE 时，请使用官方驱动工具或 Windows 的应用/设备设置单独操作。

## 反馈问题时要提供什么？

请提供：

- Vibe Flow 版本和 Windows 版本；
- 语音工具名称和版本；
- 是否安装 VB-CABLE；
- 目标应用和输入框类型；
- 自检错误码；
- 最短复现步骤，以及文字最终进入了输入框、剪贴板还是完全没有出现。

不要上传普通录音、转写文字、剪贴板内容、私人截图、完整窗口标题或蓝牙地址。
