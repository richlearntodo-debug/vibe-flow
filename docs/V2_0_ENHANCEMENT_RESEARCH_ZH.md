# Vibe Link：V2.0 功能与升级调研分析

> 目的：回答「当前 V2.0 候选版作为一个大版本还不够份量，应该增加哪些核心功能、升级优化哪些点」。
> 依据：仓库现状（`scripts/`、`docs/V2_0_*`、`CHANGELOG.md`）、本机真机实测记录（2026-09-09/10 的听写链路迭代与豆包调研）、竞品与平台技术调研（见文末来源）。
> 状态：调研稿（未提交），供产品决策；不含承诺排期。

---

## 1. 结论摘要（先看这里）

当前 V2.0 候选版的实质是「**产品面收口 + 交互链路补课**」：六页信息架构、五项任务向导真机门禁、Smart Focus 输入目标、Live HUD、受控粘贴回填、VB-CABLE 一体化、安装器与门禁体系。它把一个 1.5 的「能用」产品整理成了「讲得清、可回退」的产品，但**缺少能被用户直接感知的核心能力升级**。

要让 V2.0 站得住，建议用 **3 个旗舰能力 + 1 组工作流能力 + 5 类系统优化** 来定义：

| 类型 | 能力 | 一句话价值 |
|---|---|---|
| 旗舰 1 | **收音质量工程与「同一段音频 A/B 选引擎」** | 把「识别不准」从玄学变成可测量、可对比、可复现的工程问题 |
| 旗舰 2 | **多引擎能力矩阵 + 按应用自动路由 + 投递回执** | 任何输入框、任何语音工具，一次按键文字必达；失败可见、可重试 |
| 旗舰 3 | **可选 AI 整理（本地优先）** | 口语 → 书面语/要点/翻译，明确开关、默认关闭、不自动发送 |
| 工作流能力（低成本高感知，竞品共识） | **Smart Focus 可视化 · 工作流卡片（按键+引擎+风格） · 中文风格引导卡 · 术语包 · 遥控器多后端调度 · 双击语音键暂停 · 隐私白皮书** | 见 6.6/6.7：全行业标配的「转写之后那一层」，本产品投入产出最高的补齐位 |

| 优化类别 | 关键项 |
|---|---|
| 遥控器价值 | 组合键/长按/双击/宏、电量与断连诊断（RSSI 不可行）、语音专用动作键 |
| 听写体验 | 完成提示音与状态回执、重试投递、连续口述、实时电平/削顶提醒、轻语档位建议 |
| 目标与焦点 | 每个应用的默认目标、失败兜底、多显示器/虚拟桌面、录音前三秒体检 |
| 交付成熟度 | 代码签名（开源可走 SignPath 免费）、自动更新与回滚、便携版、诊断包导出 |
| 工程与测试 | 硬件在环用例、启动与内存/GDI 优化、托盘与悬浮窗 Win11 自愈、高 DPI 修补 |

## 2. 现状盘点：手里已有什么

### 2.1 产品资产（竞品难以复制）

1. **物理遥控器 + 专用录音键（按住说、松开停）**：真正的手离键盘场景；不依赖 PC 麦克风与前台窗口。
2. **冻结且已验证的音频链路**：RC003 ATVV → CABLE Input/Output，内核 `v1.0.3`、`1.2.1.0` 二进制被 SHA 钉死，任何语音工具只要读麦克风就能接入。
3. **Windows 深集成**：UIA 焦点学习/立即测试门禁/会话内焦点锁定与恢复、录制优先级门禁、注入按键补偿、剪贴板公开序列号观察（不读文字）。
4. **隐私架构**：不读/不存/不上传第三方转写文字，不自动回车、不自动发送；日志脱敏 `SafeLogValue`。
5. **工程门禁**：`scripts/validate.js`（钉住文案/URL/标记）、V2 功能套件、安装器迁移/需求/生命周期测试、UI 资源测试、发布包身份与哈希校验。
6. **周边工作流**：Profiles/Smart Profiles、Live HUD、Context Deck、Capture & Ask（截图提问）、Browser Remote Lite。

### 2.2 已有但「半成品」的能力（升级性价比最高）

| 已有能力 | 现状 | 升级方向 |
|---|---|---|
| 一次性音频诊断（`CaptureNextAudioDiagnostic`） | 用户触发后保存 3 份 WAV（原声/处理后/CABLE）+ 一份极简 info.txt，需人工分析 | 升级为**音质报告 + 调优向导 + 引擎 A/B**（旗舰 1） |
| 微信受控回填 | 已做到「松开→入框约 1.9 秒」，含载荷序列号等待、目标恢复、前台守卫 | 抽象成**投递策略层**（直写/回填/提示），加回执与重试（旗舰 2） |
| `custom` 语音工具 provider | 仅能填全局快捷键，无能力探测 | 升级为**引擎能力矩阵 + 自动探测 + 按应用路由**（旗舰 2） |
| Smart Profiles | 按前台进程切换按键映射 | 扩展为**按前台应用切换 引擎/投递策略/术语表** |
| 自检页 | 10 项被动检查 + 真实证据 | 增加**主动硬件端到端体检**与一键修复 |
| Live HUD | 状态可视（已定稿 Liquid Glass） | 位置记忆、点击穿透、极简模式、完成回执 |

## 3. 差距分析：为什么现在「不够 V2.0」

### 3.1 用户可感知的缺口

1. **识别质量不可控**：本机实测原始峰值多次顶到 100%（削顶）、自动增益 5–7 倍；用户遇到的「识别不准/不出字」无法归因，也没有工具去对比不同引擎对**同一段音频**的表现。
2. **没有「投递回执」**：用户不知道文字到底去了哪里、是否成功、失败原因是什么；失败时只能靠一次 Toast。
3. **引擎选择靠猜**：微信=剪贴板回填、Windows=直写但质量一般、豆包=无法自动化（厂商过滤模拟输入，已实测）、Typeless/自定义=需要手工配快捷键；产品没有把这套「能力差异」变成决策辅助。
4. **遥控器只发挥了录音键**：映射只有单键单动作，没有长按/双击/组合与宏；也没有电量/信号/断连信息。
5. **交付仍是「未签名候选」**：无签名、无自动更新、无便携版、无崩溃诊断，离「正式版」还有一段距离。

### 3.2 竞品普遍具备、本产品缺失（详见第 6 节调研表）

- AI 润色/自动格式化、去口语与自动标点；
- 自定义词表/热词、按应用模板；
- 语音指令与片段（snippets）；
- 翻译/双语投递；
- 本地模型选项与明确的隐私开关；
- 详尽的历史/统计（本产品受隐私约束，只能做元数据统计）。

### 3.3 约束（决定了「不能做什么」）

- **录音链路冻结**：不能改 Capture 二进制与内核参数（`gain=1.0`、`speech`、`drainMs=180`、约 60 秒边界、hold 语义）；任何「超长口述/实时续流」都要先评估是否越界。
- **隐私红线**：默认不读转写文字、不自动发送；任何「AI 整理/翻译/历史」都必须是**显式开启**且默认关闭，并写清数据去向。
- **第三方输入法边界**：注入输入会被部分输入法过滤（豆包已实测），产品只能「检测 + 引导 + 换策略」，不能承诺绕过。

## 4. 旗舰能力（建议作为 V2.0 的主卖点）

### 旗舰 1：收音质量工程 + 同一段音频 A/B 选引擎

**问题**：识别率的锅常常被甩给「麦克风」「引擎」，但从未被量化。

**做法**
1. **音质报告**：对已有诊断 WAV（`01-raw`/`02-processed`/`03-cable`）自动计算峰值、RMS、削顶比例、噪声底、语音段 SNR、有效语音时长，输出「结论 + 建议」（例：削顶 12% → 建议减小增益/距离 10–20cm）。
2. **调优向导**：在合规范围内对比不同采集参数（如增益/处理模式档位）对同一句话的影响，给出推荐档位并写回配置（不触碰冻结二进制）。
3. **引擎 A/B**：把 `02/03` 的音频用 NAudio（已随包分发 `NAudio.Core`/`NAudio.Wasapi`）回放到 CABLE Input，让用户对着**同一段音频**依次用不同引擎听写，产品记录「投递是否成功、延迟、是否需要回填」，由用户目视比较文本质量（产品仍不读文字）。
4. **本地试听**：可选把录音回放给用户自己听（本地、可关闭、不进入诊断日志）。

**价值**：直接命中最大痛点；把「玄学调优」变成本产品的差异化能力（竞品无此形态）。
**风险**：不改变音频链本身，改善幅度取决于源头（遥控器麦克风/蓝牙）；报告中必须如实说明上限。

### 旗舰 2：引擎能力矩阵 + 按应用路由 + 投递回执

**做法**
1. **能力矩阵**：对每个引擎维护已实测能力（直写/剪贴板回填/无法自动化、冷启动耗时、快捷键、是否需要激活输入法、已知坑），并在「语音」页以表格呈现；矩阵值由**自动探测 + 实测证据**产生（例：注入后检查剪贴板序列号是否变化、目标框文本是否变化——不读内容，只看是否变化）。
2. **投递策略层**：`直写优先 → 受控回填 → 提示手动`，策略可按引擎与前台应用配置；失败自动降级并记录原因码。
3. **按应用路由**：复用 Smart Profiles 的前台进程识别，为每个应用指定「引擎 + 投递策略 + 术语表」，例如聊天类走回填、IDE/终端走直写、笔记类走 AI 整理。
4. **投递回执**：HUD/首页显示「已投递到 <应用>（引擎/策略/耗时）」或「未投递（原因码）」，并提供**重试投递**（遥控器动作键或托盘）。
5. **一键切换**：遥控器动作键循环切换引擎，实时反馈。

**价值**：把本轮的豆包/微信教训产品化——从「我们踩过的坑」变成「用户不用踩」。
**风险**：能力探测需要真实会话；某些探测（如剪贴板序列号）必须严格限定为「只观察变化、不读取内容」。

### 旗舰 3：可选 AI 整理（本地优先，默认关闭）

**做法**：显式开启「AI 整理模式」后，会话结束时可选择：润色成书面语 / 提取要点 / 翻译；处理在**本机模型（Ollama/本地推理）优先**，云端需用户自填端点与密钥；结果写回原输入框，仍不自动发送；每次处理前提示数据去向，提供一键关闭与清除记录。

**价值**：竞品（Wispr Flow、superwhisper 等）的标配卖点，本产品缺位最明显。
**风险**：触碰隐私红线，必须默认关闭、逐次可见、可审计；文档与 UI 必须写清「此时产品会读取文字」。

## 5. 系统优化清单（按主题）

### 5.1 遥控器与硬件
- 映射升级：长按、双击、组合键、动作序列（宏，V1.5 起一直 deferred）。
- 语音专用动作：切换引擎、重试投递、取消本次听写、显示/隐藏 HUD、切换输入目标。
- **片段键（隐私安全的 Snippets）**：用户自建常用文本（地址、开场白、模板），按遥控器键直接粘贴到已验证输入框——不涉及转写内容，复刻竞品最受欢迎的能力之一。
- 设备信息：电量、RSSI/连接质量、断连与重连统计、最近一次按键延迟。
- 配对与恢复引导：首次配对、睡眠唤醒、蓝牙重启后的自动恢复可视化。

### 5.2 听写体验
- 完成/失败提示音与状态回执（`soundFeedbackEnabled` 已有，可细分音效）。
- 低音量/削顶/静音提醒（基于采集与 CABLE 侧观察，不读文字）。
- **轻语/近距离档位**：遥控器贴嘴使用时音量普遍偏大（实测削顶），在合规范围内给出「轻声说话」档位建议与诊断（对标竞品 Whisper 模式，但不改冻结链路）。
- 连续口述：多次按住自动追加到同一输入框（现行为自然支持，需明确产品语义与提示）。
- 撤销/重试：把「刚才那次投递」变成可撤销动作（发送 Ctrl+Z / 重新粘贴，均不读文字）。

### 5.3 目标与焦点
- 每个应用记住默认输入目标（多目标 Profiles），跨虚拟桌面与多显示器记忆。
- 焦点恢复失败的兜底：遥控器确认键触发「粘贴到当前焦点」。
- UWP/Electron/Chromium 变体的目标识别增强与回归用例。

### 5.4 诊断与支持
- 一键端到端体检：真实会话 → 检查音频到达、焦点、引擎回执、投递结果，给出修复入口。
- 诊断包导出：日志 + 音质指标 + 环境信息（全部经 `SafeLogValue` 脱敏），用户可自行审阅后分享。
- 统计面板（仅元数据）：会话数、成功率、P50/P95 延迟、按引擎/应用分布（对标竞品用量看板，但不触碰文字）。
- 音质档案：为「同一支遥控器 + 同一台电脑」保存历次音质报告趋势（削顶比例、噪声底），用于判断是硬件老化还是设置问题。

### 5.5 交付与工程
- Authenticode 代码签名（消除 SmartScreen 警告）；自动更新（含哈希校验与回滚）；便携版。
- 可选崩溃/异常上报（默认关闭，本地先存）。
- 启动时间、内存与 GDI 占用优化（资源测试已显示余量偏小）。
- 桥接注入失败补偿从「单次尝试」升级为有界重试（历史审计遗留 MEDIUM）。

### 5.6 面向更广人群
- 英文界面（zh-CN 为默认）与文案本地化框架。
- 无障碍：全键盘操作、屏幕阅读器标签、HUD 高对比模式。

## 6. 竞品与技术调研

### 6.1 竞品功能矩阵（检索证据）

| 竞品 | 形态 | 值得借鉴的能力 |
|---|---|---|
| **Wispr Flow**（Mac/Win/iPhone/Android） | 云端语音听写，面向「任何应用」 | 说完自动润色（去口头语、自动标点、列表化）、**Backtrack 边说边纠正**、100+ 语言、**Whisper 低语模式**、**Dictionary 个人词表**（纠正即学习 + 手工添加术语）、**Snippets 语音片段**、**Styles 按场景/应用切换语气**、团队共享词表/片段、用量看板、开发者向（语法/文件名感知）[来源](https://wisprflow.ai/features) |
| **superwhisper**（Mac/Win/iOS） | 本地模型优先的听写 + 文件转写 | **完全离线模型**、AI 模式（邮件/消息/自定义系统提示词）、**读取屏幕上下文**、自定义词表、翻译、文件转写（含说话人分离）、会议记录、企业合规（SOC 2 / HIPAA）、一次买断授权、跨平台同一套快捷键/词表/模式 [来源](https://superwhisper.com/vs/raycast) |
| **Raycast Dictation** | 启动器内置听写 | 与应用同一套快捷键体系；按应用自定义风格（Email/Messaging/custom）[来源](https://superwhisper.com/vs/raycast) |
| 中文侧（微信输入法 / 豆包输入法 / 讯飞 / Windows 语音输入） | 系统输入法语音 | 各自的上屏策略差异巨大：**直写上屏 vs 剪贴板投递**；本产品已实测三类行为并存（详见 `docs/V2_0_KNOWN_LIMITATIONS_ZH.md`）[社区讨论](https://linux.do/t/topic/2441017/17) |

**共性结论**：头部产品卖的不是「转写」，而是 **转写之后**——润色、词表、片段、按场景语气、离线隐私、跨设备一致。本产品当前恰好缺这一层，而它拥有竞品没有的**物理遥控器 + 冻结音频链路**。

### 6.2 指标口径对比（我们 vs 竞品）

| 维度 | 竞品普遍做法 | 本产品现状 | 建议 |
|---|---|---|---|
| 转写引擎 | 自研/自选模型（本地或云） | 复用第三方输入法/系统能力（不可控） | 保持「不造模型」，但把**引擎能力差异产品化**（旗舰 2） |
| 后处理 | 默认开启 AI 润色 | 无 | 可选 AI 整理（旗舰 3，默认关闭） |
| 词表/片段 | 内置并云端同步 | 无 | 遥控器触发片段 + 引擎侧词表引导（见 6.3） |
| 隐私 | 云端为主，部分本地 | **本机全链路、默认不读文字**（强于多数竞品） | 把隐私做成卖点与可审计项 |
| 触发方式 | 键盘快捷键 | **物理遥控器按住说**（手离键盘场景） | 把「离键场景」写进产品定位与场景页 |

### 6.3 适配到本产品的隐私安全变体（竞品功能 → 我们的做法）

| 竞品功能 | 直接照搬的障碍 | 本产品的合规变体 |
|---|---|---|
| Snippets 语音片段 | 需要读识别文字来匹配口令 | **遥控器片段键**：用户自建文本片段，按遥控器某个键（或组合键）→ 直接粘贴到已验证输入框；片段是用户自己的文本，不涉及转写内容 |
| Dictionary 词表 | 需要写入引擎内部词库 | ① 对可自动化的引擎（Windows 语音输入）给出「词表导入指引」；② 提供**术语表 → 遥控器片段**的替代路径；③ 语音页明确各引擎词表入口 |
| Styles 按场景语气 | 需要读文字并改写 | 由「按应用路由到不同引擎/输入法」近似实现（旗舰 2）；AI 整理模式下再做真正的风格化 |
| Whisper 低语模式 | 需要模型侧能力 | 采集侧只能调增益/处理档位：先做**音量与削顶诊断**，再评估「轻语增益档」是否合规可调（不触碰冻结二进制） |
| Usage dashboards | 涉及文字内容 | 只统计**元数据**：会话数、成功率、P50/P95 延迟、按引擎/应用分布 |
| 文件转写 / 会议记录 | 需要读取并存储文字 | 明确**不做**；仅提供「口述导出到文件/剪贴板」的用户主动动作 |

### 6.4 Windows 技术可行性结论（详见 `docs/V2_0_TECH_FEASIBILITY_ZH.md`）

**① 音频质量（旗舰 1 的技术底座）**

| 技术点 | 结论 | 关键 API / 做法 |
|---|---|---|
| 实时电平与削顶提示 | **已验证可行、隐私友好** | `IAudioMeterInformation::GetPeakValue`（CABLE Input 渲染端点，20–30 Hz 轮询，**不打开数据流、不读样本**，只返回一个浮点数）→ 悬浮窗实时电平条 + 满刻度告警 |
| 削顶归因（决定后续路线） | 需实验（**第 0 周必做**） | 同一句话用 gain 1.0/0.8/0.6 各录一遍：饱和样本随 gain 下降而减少 → 削顶在采集程序之后（可救）；几乎不变 → 削顶在遥控器麦克风/ATVV 上游（只能改声学条件与使用引导） |
| 采样率/格式对齐校验 | 需实验（成本最低、优先做） | 校验 CABLE Input（渲染）与 CABLE Output（捕获）默认格式与采集输出一致；VB-CABLE 多数可自适应，但错配是真实无声/失真源 → 自检页显式校验 + 修复指引 |
| 尾音截断 | 需实验（低风险高收益） | `drainMs` 180 → 扫 180/250/300/400 ms；尾字丢失是按住说话类产品的典型错误源 |
| 下游 DSP（衰减/高通/降噪） | 需实验（推荐方案） | 在 **CABLE Output 的 capture 阶段**挂 Equalizer APO（`Preamp: -4 dB`、`Filter: ON HP`、可选 VST 降噪）→ **冻结链路与用户配置零改动**；代价：需管理员安装、设备变更后需重绑、自检页要校验生效 |
| 自研 APO / 虚拟声卡 | **不可行** | 官方要求 APO 与驱动同包 INF 注册为 PnP 子设备，不能挂到 VB-CABLE 这类第三方驱动；自研虚拟声卡需内核签名 |
| 环回旁听（诊断模式） | 已验证可行 | `AUDCLNT_STREAMFLAGS_LOOPBACK`（仅共享模式）；涉及读音频样本 → 仅在用户显式开启的诊断模式下使用，只出数值不落盘 |

**② 交付与分发**

- **代码签名**：Azure Trusted Signing 约 $9.99/月，但**个人开发者仅限美国/加拿大**；中国大陆可选 OV/EV 证书（OV 约 ¥1500–4000/年量级）或——**本产品若开源，可用 SignPath Foundation 免费签名**。注意：签名后 SmartScreen 信誉仍需时间累积，**不能承诺「签了就没警告」**。
- **自动更新**：推荐 NetSparkle（Ed25519 签名清单 + WinForms 预置 UI）或自研「签名清单 + WinVerifyTrust 双校验 + 版本目录原子切换 + 启动健康检查自动回滚」；Squirrel.Windows 生态已迁移，不建议新项目采用。
- **便携版 / 配置保留**：`portable.flag` 决定 `%LOCALAPPDATA%` 还是 `<exe>\data`；**配置必须放在版本目录之外**，否则升级即丢配置；免管理员（`%LocalAppData%`）与 uiAccess（需 Program Files）互斥，是安装位置的硬取舍。

**③ 遥控器状态**

- **电量**：可走 WinRT `Windows.Devices.Power.Battery`（经 `Microsoft.Windows.SDK.Contracts`，.NET Framework 未打包应用可用）或回落 GATT `0x180F`/`0x2A19`；**容量字段常为 null，必须做「无数据即隐藏」降级**；采集程序长连接遥控器时宿主再连可能失败 → 只读、失败即降级，绝不影响录音链路。
- **RSSI / 信号强度：不可行**（连接态无受支持 API）→ 只能用 `ConnectionStatus`、GATT 读往返耗时、HID 事件间隔抖动做代理指标，**不要在 UI 承诺信号强度**。
- **断连事件**：`ConnectionStatusChanged` + `DeviceWatcher`（需 2–3 s 去抖）；配对必须引导到系统「设置 → 蓝牙」（`PairAsync` 桌面应用不支持）。

**④ 输入集成边界（对旗舰 2 影响最大）**

- 输入法过滤注入的机制是公开契约：低级键盘钩子的 `KBDLLHOOKSTRUCT.flags` 含 `LLKHF_INJECTED`，输入法只要挂钩子即可整体丢弃注入按键；原始输入还能区分注入事件的「伪设备」。→ **豆包案例是架构性上限，不是实现缺陷。**
- **最高价值的替代路径：UIA 直接写值** —— `ValuePattern.SetValue` → `LegacyIAccessiblePattern.SetValue` → `TextPattern`，**完全不产生键盘事件**，天然绕过注入过滤；限制：目标需暴露可写 provider、React 类受控组件可能不同步、跨完整性受 UIPI 限制。⚠️ 该路径需要先取得文本（对微信输入法即剪贴板），因此**只能作为显式开启的投递模式**，并在 UI 声明「此时会瞬时读取剪贴板文本、不落盘不上传」。
- 消息级写入（`WM_SETTEXT`/`EM_REPLACESEL`）可作为经典 Win32 控件的兜底；TSF 文本服务（需注册系统级 TIP、管理员安装、周级工作量）与虚拟 HID 驱动（内核签名、与木马行为相似）**明确不做**；uiAccess 可解决「管理员窗口收不到输入」但**不去除注入标记**，对反注入输入法无效。

**⑤ 性能、DPI 与 Win11 兼容**

- 高 DPI：`app.config` 声明 `DpiAwareness=PerMonitorV2`（.NET FW ≥ 4.7）+ `DpiChanged` + `LogicalToDeviceUnits`，禁止固定像素自绘；混合 DPI 双屏是重点用例。
- 启动/内存：`generatePublisherEvidence=false`、NGen、把音频设备与 BLE 初始化移出 `Main`、自检页延迟构建；做 8 小时 + 500 次页面切换的 GDI/句柄回归。
- 托盘/悬浮窗：必须处理 Explorer 重启（`TaskbarCreated` 重新 `NIM_ADD`，并提供「一键修复托盘图标」）；悬浮窗用 `WS_EX_NOACTIVATE` + `SWP_NOACTIVATE`（保住现有焦点锁定）、DWM 圆角/背景（**Mica 对分层窗口无效，与半透明二选一**）、`WDA_EXCLUDEFROMCAPTURE` 可让悬浮窗不进屏幕共享。
- Toast 通知在**提权运行时不支持** → 提权场景继续用托盘气泡；任务栏进度/缩略图工具栏（`ITaskbarList3`）可用于更新进度与「开始/停止录音」。
- 全局快捷键优先 `RegisterHotKey` + `MOD_NOREPEAT` 并做占用冲突检测（低级钩子有 1000 ms 超时被系统静默移除的风险，仅在必须抑制按键时使用——遥控器触发应走其自身 HID 事件）。
- **不建议迁移 WPF/WinUI**：重写成本远超观感收益，且最贵的焦点/注入/托盘链路已经调通；观感用自绘 + DWM 圆角即可。
- **Win11 小组件 / 快速设置：不可行**（小组件要求 MSIX 打包应用 + Windows App SDK；快速设置无第三方扩展 API）。

### 6.6 竞品调研的最强结论（完整报告见 `docs/V2_0_COMPETITIVE_RESEARCH_ZH.md`，77 条来源）

1. **「按应用切换」已是全行业标配，且跨到了硬件侧**：Typeless 免费档就给 per-app tones；Diction Tones、VoiceInk Power Mode（按前台进程 + 浏览器 URL 切模型/词典/标点）、Elgato Stream Deck 的 Smart Profiles 也按应用切配置。**本产品 Smart Profiles 目前只切按键表 → 升级为「工作流卡片」（按键表 + 推荐语音工具 + 风格提示）是投入产出最高的缺口。**
2. **「输入目标定位」是被验证的行业级痛点，也是本产品最被低估的资产**：官方与第三方都承认听写在「说完→落字」间隙会因焦点漂移写错窗口，而竞品**普遍只能要求用户自己先点好输入框**——**没有一家做「开始录音时锁定目标 + 会话内恢复」**。Smart Focus 只需 UI 化/可解释化即可成为品类首创。
3. **「物理触发器 + 语音」已被头部厂商用硬件验证**：Wispr Flow 官方卖 **Wispr Pedal（$199，预映射 Flow + 1 年 Pro）**，Elgato Stream Deck Pedal $89.99。**本产品用一支廉价 RC003 做同样的事，具备结构性成本优势**，这是最值得写进对外定位的叙事。
4. **同形态直接竞品确凿存在**：`ZSTDJan/windows-remote-mic-app`（无线麦 Win 版）同样适配 RC003：13 键 + 单击/双击/长按/组合 + 按住说话 + CABLE 桥接 + 搜狗/微信/Win+H/豆包适配；但**需管理员权限、v0.2.0 未签名、定位偏按键映射工具**，缺 Smart Focus / 首设向导 / 自检体系。macOS 侧 `nijez/open-voice-bridge` 已在同款遥控器上实现「长按=说话 / 双击语音键=暂停桥接」双模——**这是不改冻结内核就能拿到的第二触发模式**。
5. **隐私是最大、且竞品正在自我削弱的差异点**：Wispr Flow 的 trial/standard 账号**默认**用 audio/transcript/edits 训练模型，Zero Data Retention 需两个开关同时满足，转写始终在云端；Typeless 营销称 on-device 但音频实际在云端。**本产品「不读/不存/不上传」是架构事实而非设置项** → 应做成白皮书级卖点。
6. **剪贴板投递是技术债**：开源听写工具几乎全部走「存剪贴板→覆写→Ctrl+V→sleep→恢复」，必然带来剪贴板污染（含微软云剪贴板）、UIPI 静默失败、恢复竞态；且那些 clipboard opt-out 格式只是协作协议、非强制。→ **不要为「常用文本片段」引入剪贴板路径**；若要做，应优先走 6.4 里的 **UIA 写值**（无剪贴板、无注入）。
7. **中文胜负手在标点/数字/口语清理，不在方言数量**：Win+H 官方确认把中文数字强制归一化为阿拉伯数字且**无开关**，「流畅听写」去语气词**仅英语区域**；微信「整理文字」、豆包「智能文字整理」证明中文用户需要这一层。→ **「中文输出风格引导卡」是本产品零成本可抢的差异化位。**

## 8. 明确「不做」清单（避免再次踩坑）

1. **不改冻结录音链路**（含「超长口述/实时续流」除非单独评估与重新冻结）。
2. **不试图绕过第三方输入法的安全过滤**（豆包案例已证明不可行），只做「检测 + 引导 + 换引擎」。
3. **不默认读取转写文字**：AI 整理/翻译/历史必须是显式开关；UIA 写值投递若需读取剪贴板文本，只能作为显式开启的模式并在 UI 声明「瞬时读取、不落盘、不上传」。
4. **不自动发送**：发送永远由用户按确认键触发。
5. **不新增第二套入口体系**（V2 已把入口收口为六页）。
6. **不做历史记录/检索、云同步、团队词库**（与「不保存转写文字」硬冲突）——反过来写成隐私卖点。
7. **不用剪贴板做「常用文本片段」**：剪贴板污染 + UIPI 静默失败 + 恢复竞态；片段优先走 UIA 写值。
8. **不做自研 APO/虚拟声卡、TSF 文本服务、虚拟 HID 驱动、WPF/WinUI 重写、Win11 小组件与快速设置**（成本与风险远超收益）。
