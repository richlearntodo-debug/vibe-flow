# Issue #2：升级后无真实音频的回归结论

关联问题：[升级 1.2.0 后无法语音输入](https://github.com/richlearntodo-debug/vibe-flow/issues/2)

## 结论

Issue 中的诊断显示 `真实音频覆盖 0.1%`、`MIC_EXTEND 2 次`、多个连续分段以及单击切换录音。这是 V1.2.0 长录音续流状态机的故障，不是界面或文字回填问题。

V1.2.1 已撤销该方案并恢复经过真机验证的 `v1.0.3` Capture 内核。V1.5 继续逐字节固定同一个 Capture 二进制，因此该故障路径在 V1.5 中不存在：

- 只支持按住录音、松开结束；
- 单段由 RC003 自然音频流控制，约 60 秒；
- 不发送 `MIC_EXTEND`，不做自动续流；
- 不使用剪贴板转写回填；
- Capture 二进制 SHA-256 固定为 `B62DE035A9CAD0A16B97F6935C6E4DE0BF2B73C61B180595482D852C0582E683`。

## 可验证回归标准

在 V1.5.0 上按以下步骤复测，全部通过后可关闭 Issue：

1. 自检确认版本为 `1.5.0`，录音内核为 `v1.0.3`，语音模式为 `hold`；
2. 聚焦一个文本输入框，完成 10 秒、30 秒和接近 60 秒的按住说话测试；
3. 每次松开均只结束一次，不出现第二个麦克风会话；
4. 日志出现一组对应的 `REMOTE STREAM START` / `REMOTE STREAM STOP`；
5. 日志不出现 `MIC_EXTEND` 或 `LONG DICTATION`；
6. 真实音频覆盖不再为接近 0%，文字由所选语音工具直接进入聚焦输入框。

## 已有自动门禁

`npm test` 会验证冻结源码与二进制哈希、按住说话契约、重复 DOWN/UP 去重、无长录音续流路径以及 V1.5 组件版本一致性。硬件音频覆盖率仍必须由 RC003 真机验证，CI 不能伪造。
