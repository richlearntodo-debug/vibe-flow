# V1.3 按键路由根因报告

## 结论

V1.3 旧候选版的快捷键不是“偶发失效”，而是执行架构存在循环依赖：

```text
低层键盘 Hook 先收到事件
  -> 为避免普通键盘冲突而拦截
  -> Windows 不再投递对应 WM_INPUT
  -> 应用拿不到 RC003 设备身份
  -> 映射动作永远不会执行
```

因此，继续增大等待时间、重装蓝牙或重复保存配置都不能解决问题。

## 真机证据

旧候选包 `Vibe-Flow-v1.3.0-Hardware-Candidate-20260902-014755` 的日志显示：

| 证据 | 结果 |
| --- | ---: |
| 被 Hook 暂存后回放的键盘边沿 | 166 |
| 真正到达 RC003 Raw Input 的键盘边沿 | 4 |
| Hook 与 Raw Input 成功配对 | 0 |
| 由实体 RC003 路由的映射动作 | 0 |

同一份日志中，“页面测试”可以成功执行复制或启动应用，因为该按钮直接调用动作执行器，没有经过实体遥控器、Hook、Raw Input 和按键解析链路。这就是旧测试假阳性的来源。

本机 WinRT 探测还确认：RC003 暴露标准 HID 服务 `00001812-0000-1000-8000-00805f9b34fb`，但 Windows 对应用读取其特征返回 `AccessDenied`。普通桌面应用无法绕过系统键盘栈直接订阅该 HID 报告。

## 当前架构

### 无签名过滤器

```text
RC003 非录音键
  -> Hook 放行，不执行动作
  -> Raw Input 携带 RC003 设备句柄
  -> 去重按下/松开边沿
  -> 统一配置解析
  -> 动作执行器
```

该模式的保证：

- 普通键盘同名键不会触发遥控器动作；
- RC003 实体动作不再依赖 Hook/Raw 时序配对；
- 重复 `DOWN` 和重复 `UP` 不会创建重复动作；
- 配置 revision、设备边沿、动作边沿和最近动作均可在自检中核验。

该模式的边界：

- 因 Hook 必须放行，遥控器原始键的系统效果可能与配置动作同时发生；
- 这是 Windows 用户态的可见限制，不应在 UI 或发布说明中描述为“精确拦截”。

### 有 Microsoft 签名过滤器

```text
RC003 HID 键盘包
  -> 精确设备过滤器拦截目标扫描码
  -> 用户态读取已拦截边沿
  -> 统一配置解析
  -> 动作执行器

普通键盘
  -> Windows 原生路径
```

这是同时满足“遥控器无原始副作用”和“普通键盘零冲突”的完整行业路线。候选驱动在完成 Microsoft 签名、Secure Boot、内存完整性、多机型安装/卸载和故障回退验收前，不进入普通用户包。

## 录音链路

本轮不修改 `VibeMicAtvvCapture.cs`。以下已验证参数保持冻结：

- 录音内核 `v1.0.3`；
- 按住开始、松开结束；
- RC003 单段约 60 秒；
- 增益 `1.0`、`speech` 处理、`180 ms` 排空；
- `CABLE Input` / `CABLE Output` 自动可逆路由；
- 微信输入法 `Ctrl + Win`、toggle、`80 ms`；
- 不使用剪贴板回填。

## 发布门禁

V1.3 只有在以下真机检查全部通过后才能替代 V1.2.1：

1. 每个公开按键的实体事件都增加 `raw_remote_edges`；
2. 每个已配置动作都增加 `raw_action_edges` 或 `filter_action_edges`；
3. 日志出现 `RC003 action routed source=raw_input` 或 `source=device_filter`；
4. 普通键盘同名键连续测试不触发遥控器动作；
5. APP、URL、截图、自定义快捷键均通过实体遥控器测试；
6. 蓝牙重连、遥控器休眠、Windows 睡眠恢复后无需重新配置；
7. 录音 100 次按下/松开与约 60 秒边界回归不变。

构建、自测和页面“测试动作”都不能替代上述真机门禁。
